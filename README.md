# Selectel Floating IP Hunter

Асинхронный Telegram-бот на Python 3.11+, aiogram 3, aiohttp и SQLAlchemy/SQLite. Бот хранит credentials в зашифрованном виде Fernet, выполняет поиск через BURST-планировщик с постоянной очередью и сохраняет найденные Floating IP. Инструкция обновления, устройство очереди и ограничения восстановления: [UPGRADE.md](UPGRADE.md).

## Локальный запуск

```bash
python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
python -m app.main
```

Заполните `BOT_TOKEN`, `ADMIN_IDS` и `ENCRYPTION_KEY`. Доступ ограничивается списком Telegram ID; остальные пользователи получают отказ.

`NOTIFICATION_CHAT_ID` — ID Telegram-супергруппы с включёнными Topics. Бот должен быть администратором с правом управления темами. При добавлении аккаунта бот создаёт отдельный topic; туда отправляются сообщения о добавлении, ошибках API и найденных IP.

Главный экран показывает состояние поиска и интервал между запусками. Расписание
и найденные IP разбиты на страницы; кнопка «Обновить» загружает актуальные данные.
Из расписания можно открыть карточку аккаунта. Добавление аккаунта занимает шесть
шагов с отменой и возможностью пропустить прокси. Время запусков и результатов
в интерфейсе показано в ЕКБ (UTC+5); суточная статистика сохраняет границу дня по МСК.

Обновлённое меню сохраняет выбранный город в БД: Москва — ru-2, Санкт-Петербург —
все остальные регионы конфигурации (ru-1, ru-3, ru-9). «Мои задания» содержит
живые карточки, подтверждение остановки и историю IP. `/stats` открывает статистику
по городам. В настройках интерфейса задаются UTC-смещение и период обновления;
новые экраны и уведомления используют выбранный часовой пояс.

При добавлении аккаунта можно указать отдельный proxy (`http://user:password@host:port`). Proxy хранится зашифрованным вместе с паролем. В разделе «Запустить ловлю IP» выберите аккаунт, регион и одну или несколько подсетей. Каждая подсеть получает отдельное задание; другие регионы и аккаунты сохраняют свой выбор. Интервалы определяются настройками BURST.

## Ubuntu 22.04/24.04 и systemd

```bash
sudo apt update && sudo apt install -y python3 python3-venv python3-pip git
sudo mkdir -p /opt/selectel-ip-hunter
sudo cp -r . /opt/selectel-ip-hunter
cd /opt/selectel-ip-hunter && python3 -m venv venv
source venv/bin/activate && pip install -r requirements.txt
cp .env.example .env && nano .env
sudo cp selectel-ip-hunter.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now selectel-ip-hunter
sudo journalctl -u selectel-ip-hunter -f
```

API credentials вводятся через Telegram wizard. Пароль не попадает в логи или сообщения.

На один круг аккаунта используется один клиент и одна HTTP-сессия. Соединения
повторно используются между запросами к одному API, в том числе через прокси.
В конце круга сессия закрывается также
при ошибке или отмене. После сетевого сбоя соединение может быть пересоздано.
Разные региональные API используют отдельные соединения внутри одной сессии.
Таймаут API по умолчанию остаётся 5 секунд.

Начала BURST распределяются по расписанию с интервалом
`burst_cooldown / число активных аккаунтов` (120 секунд / 21 ≈ 5,7 секунды).
Аккаунт №1 начинает в 0 секунд, №2 — в 5,7 секунды, №3 — в 11,4 секунды,
а №1 снова — в 120 секунд. Ожидание ответов других аккаунтов не задерживает
запуск. Дополнительной паузы после завершения BURST нет: период отсчитывается
между запланированными началами. Внутри аккаунта подсети проверяются последовательно.
Если предыдущий BURST того же аккаунта ещё выполняется, пропущенные слоты
пропускаются без одновременного повторного запуска и без догоняющей пачки.
HTTP 429 сохраняет отдельную паузу Retry-After, которую ручной запуск не отменяет.
